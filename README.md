## 首次部署

1. 解压 `Where_Habit_Take_Root_7.48_Netlify.zip`，将 `Where_Habit_Take_Root` 内的文件上传到 GitHub 仓库根目录，保留 `dist/`、`lib/`、`netlify/` 的目录结构。
2. 将 Netlify 项目连接到仓库和部署分支。根目录 `netlify.toml` 指定发布目录为 `dist`，函数目录为 `netlify/functions`。
3. 在 Netlify 为 Functions 设置 `OPENAI_API_KEY`。默认模型由 `lib/photo-ai.mjs` 定义，可用 `OPENAI_MODEL` 覆盖。密钥只存放在环境变量。
4. 部署后访问站点的 `/api/analyse`。GET 返回配置状态和模型名称，无需调用模型；上传照片并点击 Generate 才能验证实际识别。

单文件 HTML 是本地预览版，直接打开时使用本地轮廓预览。部署使用本压缩包，线上分析由 Netlify 函数执行。

## 使用说明

- Generate 可复用短期缓存。Re-analyse 发起新的识别请求。调整颜色、尺寸、拖动容器和浇水均不调用模型。
- 照片清晰、背景简单、容器边缘和开口可见时，识别通常更容易。已有收藏保存在当前浏览器。
- Netlify 版本的 Featured Displays 保存在当前浏览器的 IndexedDB。使用 `npm start` 运行项目自带的 Node 服务时，可由该服务保存并共享展品。
- Story 的分享地址由 `dist/site-config.json` 配置；页面保留内置备用地址。Film 首次打开时加载，需要网络。
- Quicksand 与思源黑体子集及字体许可位于 `dist/assets`。

## 7.46 编织显示

增强可信编织区域的交错明暗和笔触粗细。轮廓、色块、把手镂空及识别门槛不变；无需重新识别已有的可信编织数据。不为未识别出编织的区域添加纹理。

## 7.47 绘制与存储负载

缩略图缓存按画布像素限制为 24 MiB、最多 32 张，淘汰时释放画布；这不是整个网页的内存上限。整只容器的编织笔触共享绘制预算，不增加模型输出。导入旧收藏与接收识别结果时校验轮廓和数值，最多保留 128 个外轮廓点、8 个镂空及 10 个色区，每个局部轮廓最多 48 点；无效收藏仅从本次显示中跳过，读取时不重写原存储。历史仅加载最近 12 项。收藏写入失败时回滚本次修改并保留编辑窗口。旧的全局纹理及划痕字段不再进入新照片收藏。模型、图片分辨率和后端未改动。
